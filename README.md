# JudgeFlow

Self-hosted платформа судейства конкурсов, хакатонов и питчей. Организатор настраивает мероприятие,
судьи оценивают команды по личным ссылкам (в том числе без сети), зрители смотрят рейтинг в реальном времени.

Весь продукт — один бинарник `judgeflow` (Rust + SQLite) со встроенным веб-интерфейсом.
Без Redis, Nginx и Node.js в рантайме: в простое занимает единицы мегабайт памяти.

> Предыдущая версия (FastAPI + Next.js + PostgreSQL + Redis) сохранена в ветке `v1`.

## Возможности

- **Жизненный цикл**: черновик → оценивание → оценивание закрыто → итоги подведены → опубликовано.
  Публикация результатов — отдельное действие; повторное открытие требует причины и пишется в журнал.
- **Judge Desk**: режимы «по командам» и «по критериям», горячие клавиши, сдача судейского листа,
  offline-first (IndexedDB + Service Worker на HTTPS), явный индикатор синхронизации.
- **Control Room**: импорт команд вставкой из буфера, критерии с весами/максимумом/шагом, ссылки и QR для судей,
  матрица «судьи × команды», результаты (предварительные и официальные), объявления для судей,
  фон и оверлей, журнал действий, экспорт CSV.
- **Live-страница** с настраиваемой видимостью: скрыто до публикации / только итоги / итоги с разбивкой по критериям.
- **Честный подсчёт**: неоценённое ≠ 0, в официальный результат идут только сданные листы, кворум,
  точная рациональная арифметика, ничьи помечаются, а не разбиваются молча.
- **Stage Mode**: экран для проектора и OBS-виджет (`/stage/:id?widget=1`) с управляемым раскрытием мест
  (3-е → 2-е → 1-е), пьедестал и турнирная таблица.
- **Треки и распределение**: свои критерии и рейтинг для каждого трека, автоматическое и ручное назначение
  судей, конфликты интересов, шаблоны критериев («Хакатон», «Питч», «Конкурс проектов»).
- **Раунды и попарное сравнение**: следующий раунд из лучших команд в один клик; режим «Кто сильнее?»
  с рейтингом Bradley–Terry (победы/поражения/ничьи видны в результатах); гибрид «рубрика → финал попарно».
- **Нормализация (по желанию)**: центрирование оценок, убирающее «строгость» отдельных судей;
  исходный балл всегда показывается рядом.
- **Аварийный экспорт листа**: судья скачивает файл со своими оценками, организатор загружает его,
  если устройство так и не смогло синхронизироваться.
- **Доступ**: вход организаторов только по TOTP, owner приглашает админов одноразовыми ссылками;
  токены судей хранятся в виде хеша, ссылку можно отозвать и перевыпустить.

Подробная спецификация — [`docs/SPEC.md`](docs/SPEC.md).

## Быстрый старт

### Docker

```bash
docker compose up -d --build
docker compose logs judgeflow   # одноразовый пароль первого запуска
```

Контейнер работает от uid 65532. Если вместо именованного тома смонтирован каталог (`./data:/data`),
он должен быть доступен этому пользователю на запись: `sudo chown -R 65532:65532 ./data`.

### Без Docker

Нужны Rust (stable) и Node.js 22+ только для сборки.

```bash
make build                      # web/dist + cargo build --release
./target/release/judgeflow      # данные в ./data
```

Готовые статические бинарники (x86_64 / aarch64, musl) и образ `ghcr.io/<owner>/<repo>` публикуются
при пуше тега `v*`.

### Первый запуск

1. При старте без администраторов сервер печатает в лог одноразовый пароль и адрес `/firststart`.
2. Откройте `http://<адрес>/firststart`, введите пароль и имя, отсканируйте QR в приложении-аутентификаторе
   и подтвердите кодом — вы владелец (owner).
3. После этого `/firststart` отвечает 404. Остальных админов owner приглашает в разделе «Админы».

## Настройка

Все переменные необязательны (см. [`.env.example`](.env.example)):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JUDGEFLOW_ADDR` | `0.0.0.0:8080` | адрес прослушивания |
| `JUDGEFLOW_DATA_DIR` | `./data` | SQLite, загрузки, `secret.key` |
| `JUDGEFLOW_PUBLIC_URL` | из `Host` запроса | база для ссылок судей и QR |
| `JUDGEFLOW_SECRET_KEY` | генерируется в `DATA_DIR/secret.key` | ключ шифрования TOTP-секретов |
| `JUDGEFLOW_TRUST_PROXY` | `false` | брать IP клиента из `CF-Connecting-IP` / `X-Forwarded-For` (для лимита попыток входа); включайте только за прокси или туннелем; приложение должно быть недоступно напрямую (порт на `127.0.0.1` или не публиковать), иначе IP можно подделать |
| `RUST_LOG` | `info` | уровень логов |

Резервная копия — это каталог `DATA_DIR` (при остановленном сервере или через `sqlite3 .backup`).

## Варианты развёртывания

- **VPS** (хватает 1 vCPU / 512 МБ): Docker или бинарник + systemd, HTTPS через любой reverse proxy.
- **Домашний ПК + Cloudflare Tunnel**: бесплатный HTTPS, пример сервиса `cloudflared` закомментирован в `compose.yaml`.
  Задайте `JUDGEFLOW_TRUST_PROXY=true`, иначе все клиенты за туннелем делят один лимит попыток входа.
  При этом публикуйте порт только на loopback (`127.0.0.1:8080:8080` в `compose.yaml`): при прямом доступе к порту заголовки подделываются.
- **Event in a Box** — ноутбук в локальной Wi-Fi без интернета: укажите `JUDGEFLOW_PUBLIC_URL=http://<LAN-IP>:8080`.
  Без HTTPS Service Worker недоступен, но оценки всё равно сохраняются на устройстве судьи в IndexedDB.

## Администрирование (CLI)

```bash
judgeflow admin list
judgeflow admin reset-totp <name>   # новый QR; единственный способ сбросить TOTP владельца
judgeflow admin set-owner <name>
```

## Разработка

```bash
cargo run                     # API на :8080
cd web && npm run dev         # Vite с прокси /api → :8080
make test                     # cargo test + vitest
make lint                     # fmt, clippy, typecheck, eslint
make e2e                      # Playwright против реального бинарника
```

Структура: `src/` — сервер (Axum, SQLx), `src/ranking.rs` — чистый движок рейтинга, `migrations/` — схема SQLite,
`tests/` — интеграционные тесты API, `web/` — React-интерфейс, `web/e2e/` — E2E.
